# 如何复验这版界面

**先看交付物，再看数字。** 在空单按成片、星轨、延时的顺序选择，直接比较三次显示的照片；点延时编号帧，检查构图保持、天空随时间变化。没有导入照片时进入素材页，不应把演示当作原片。导入后清楚标注原片；文件坏了就报告预览不可用。

在保存步骤展开曝光微调，再进「冲印参数」调整曝光并返回。前后只应有一个页首、一份参数和同一张单。源预览上的曝光试样与正式 RAW 成片不同；退回 0 EV 恢复原预览，不能因此获得成品回执或导出资格。另核对已有正式结果的分屏放大位置、精修蒙版和已选素材。

常规本机检查：CMake 配置 `BUILD_TESTING=ON`、`BUILD_SAMPLE_TOOLS=ON`，构建后运行 `ctest --test-dir build -C Release --output-on-failure`。检查程序随包实际解码全部照片可运行 `StarProcessor --platform-runtime-check`。这些都不能当作系统标题栏验收。

**macOS 整窗。** 在有图形会话的本机启用 `-DNEBULENS_BUILD_DESKTOP_QA=ON`（录屏工具需 macOS 15+ SDK 与系统），构建 `NebulensDesktopWalkthrough` 与 `NebulensPaperChromeTests`。按 [工具说明](../../tools/desktop_qa/README.md) 录制连续操作；命令 `NebulensPaperChromeTests --input` 另行检查原生窗控命中、拖动、双击、全屏及关闭。不要在另一任务正在驱动前台窗口时同时操作。源图和私有录屏不要加入 Git。

验收分开记录：可访问状态和可点击区域用测试检查；窗控安全区用原生窗口几何和含三个系统按钮的截图检查；接下来是否该点哪一步，以连续动作和实际画面判断。对真实数据的处理仍需独立检查输出像素。Windows 的 DWM 实现与左右窗控预留布局已纳入代码，Mac 上的验证不等于 Windows 实机通过。

2026-11-27 的本机验收分三项：

1. **行为**：Mac Release 全部 20 组 CTest 通过，包括双语、损坏原片、折叠键盘操作、两侧窗控预留、试样与正式成品隔离；安装包需实际解码纸纹与全部 7 张摄影印样。
2. **视觉与操作**：实查 920×540 英文和 1280×740 中文的完整 Cocoa 窗口。独立原生烟测验证窗控命中、系统拖动/双击、最小化、绿键全屏/缩放和关闭。约 24 秒连续录屏中，五帧延时可翻看、真实 RAW 就绪后进入参数、改曝光并返回原保存步骤。固定照片区域从 +0.2 EV 到 +1.0 EV 的平均显示亮度（0–255）由约 55 升至 73；不是仅滑块数值变化。文件选择器是另一窗口，主窗口录像不含它或桌面其他应用。
3. **成片**：私有样片的实际 GUI 重放仍为 9 张提交、7 张采用，5900×3931 RGB16 成片与基准逐像素一致。未发布私人素材或录像，未使用 GitHub Actions。Windows 版本未在本轮作实机验收。
