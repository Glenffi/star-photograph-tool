# StarProcessor v0.11.0 发布前审查

> 审查日期：2026-08-24  
> 范围：`v0.10.2..main` 代码、测试、macOS/Windows 打包与真实样片  
> 结论：未发现 P0；发布前确认的 P1 已修复，可进入正式发布验证。

## 已修复问题

| 优先级 | 问题 | 修复 |
|---|---|---|
| P1 | 素材增加、删除或排除后，快捷键仍可能导出旧结果 | 把按顺序规范化的参与素材集合纳入上游签名；工具栏和导出入口使用同一签名校验。 |
| P1 | 新任务取消/失败后无法返回上一张有效成片 | 独立保留有界 8-bit 结果预览；新任务失败或取消后恢复只读结果槽，不恢复导出资格。 |
| P1 | 切换素材后编辑蒙版不可见，但正式处理仍使用隐藏蒙版 | 回到蒙版来源帧时恢复编辑硬蒙版与叠加，不增加蒙版 revision。 |
| P1 | QSettings 参数在启动时被场景默认值覆盖 | 首次安装才应用场景默认；已有持久化参数只更新场景可见性。 |
| P1 | 删除/撤销参考帧后左右面板不同步 | 删除和撤销参考帧均发射 `referenceFrameChanged`，处理选择与 UI 保持一致。 |
| P1 | 撤销参考帧期间重新指定参考帧，可能留下两个参考标记 | 恢复旧参考帧前先清除临时参考标记，并增加重复撤销回归。 |
| P1 | 单张精修切换素材后仍可导出上一张结果 | 处理签名加入场景和单张模式实际使用的当前素材；切换素材立即重算结果有效性。 |
| P1 | 历史预览返回当前结果后导出按钮未恢复 | `R` 和结果入口统一按当前签名重新同步导出状态；历史结果本身始终只读。 |
| P1 | 全局单键快捷键抢占复选框、滑杆和下拉框按键 | 应用级快捷键避开所有标准交互控件，保留控件自身键盘行为。 |
| P1 | 重启恢复的堆栈算法被帧数推荐再次覆盖 | 把持久化算法视为用户明确选择，导入时不再自动替换。 |
| P1 | 历史 TIFF 先分配完整 RGB16，超大/伪造文件可能耗尽内存 | 在 libtiff 扫描行阶段直接缩到 2400px；只接受本应用生成的无压缩、单行 strip TIFF，并增加格式、分配、扫描行和异常边界。 |
| P1 | 历史 TIFF 解码不能协作取消，关闭窗口可能长时间等待 | 每个输出扫描行检查中断；worker 增加异常边界，tone mapping 只处理有界图像。 |
| P1 | Windows 最终便携目录未实际加载 Qt 平台插件 | 打包 CI 在复制全部 DLL 后先验证静态运行库，再通过 `--platform-runtime-check` 初始化 `QApplication`，实际加载 `qwindows.dll`。 |

## 同步改进

- 窗口硬下限由 1180×760 调整为 920×540，以覆盖 1920×1080 屏幕的 200% 系统缩放；1180×760 仍是建议尺寸。
- 单键快捷键改为应用级事件过滤，在下拉框/滑杆获得焦点时仍有效；文本输入、菜单和模态对话框不会被拦截。
- 素材卡获得键盘焦点时同步成为当前素材并绘制焦点框。
- TIFF 读取校验 `PHOTOMETRIC`、`SAMPLEFORMAT`、planar config、orientation 和 tiled 状态。
- macOS 本地打包依赖高于目标版本时默认中止，避免把仅适用于新系统的 DMG 当作公开包。
- Unicode TIFF 读写、解码取消、下采样、素材签名、参考帧撤销、视图蒙版恢复和参数重启持久化均加入回归测试。
- 取消或失败任务只保留有界的上一结果预览；浏览素材后仍可返回，但旧结果不获得导出资格。

## 残余风险

- macOS GitHub runner 不执行 Cocoa GUI 截图，因为无图形会话；CI 仍执行 9 组测试、动态库闭包和包内运行时自检，本地正式 DMG 另行执行真实 GUI 启动截图。
- 工具栏图标由 Qt 运行时栅格化；200% 截图未发现明显发虚，后续获得 Windows 多种缩放比例实机反馈后再决定是否增加显式多 DPR 状态图。
