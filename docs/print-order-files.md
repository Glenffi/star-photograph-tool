# 冲印单与山脊示例

在冲印单页首选择「冲印单 → 保存冲印单」，或用「文件 → 冲印单另存为…」另起一份。这里保存的是制作方法；「保存成品」才会执行正式处理并写出 TIFF、PNG 或图片序列。可从「打开冲印单」或桌面程序命令行传入一个 `.nebprint` 文件重新打开。

**重开时保留什么？** 素材的原有顺序、排除项、当前选片、参考帧、深空校准源、场景和调整参数、输出格式与目录。手修地景蒙版的像素及绑定帧写在单据内，外部导入的蒙版则和 RAW 一样按文件位置关联。不会把原片复制进单据，不会自动生成成片，也不会恢复旧回执。

**搬家后怎么办？** 尽量保持单据、原片、外部蒙版的相对目录结构。只移动素材时，首次重开会提示选择含有指定文件的新目录，同一目录的其他素材一起重定位；保存单据即可记住新位置。不同目录下的同名文件不会被全局按名字替换。取消或打开失败不会清空当前窗口。

## 看三路山脊对照

打开示例单，点「山脊对照」。从左到右依次是参考单张、只对齐天空的普通堆栈、以及天空对齐而地景在原位合成的天地分离。先看远山与夜空交界处是否出现第二层轮廓，再看山体纹理。用「适合窗口」看全貌，「100%」看同一位置的细节。裁片是生成示例时的记录，不会因后来调节滑块而冒充新结果。

示例包的 PNG 即使没有 NAS 也可以单独打开。要重开整份单据并实际重新处理，需能访问原片及原始外部蒙版。单据中的路径、照片、裁片和 GPS 信息不要未经授权公开。

示例附带的三张裁片记录的是制作示例时的结果。重新处理后，要核对这一次是否仍用了同一批原片，请在新回执里看「用片明细」。打开一张明细里的原片只是查看，不会把它设为参考帧，也不会改变已经保存的成片。

## 在本机制作自己的示例

生成器使用 Python 3.10+、NumPy 和带 FreeType 的 Pillow 10.1+，CMake 构建启用 `BUILD_SAMPLE_TOOLS`。桌面客户端不需要这些 Python 依赖。下面的参考索引以 0 开始。ROI 是转正后的参考 RAW 坐标（左、上、宽、高），不是预览窗口的坐标。省略 ROI 时工具尝试从地景蒙版取地平线，应目视确认取到的确实是山脊。

```bash
python3 tools/lake_example/generate.py run \
  --runner ./build/StarProcessorPipelineRunner --input "/path/to/raw-sequence" \
  --start-index 0 --limit 9 --reference-index 4 --output "/path/to/new-example"
```

可以用 `--user-mask /path/to/mask.png` 提供人工修补的二值原始蒙版（白色天空、黑色地景），不要把已经羽化的诊断图作为输入。两组堆栈使用相同参考帧、相同算法；生成器核实实际采用的帧一致才输出。三份裁片分别扣除成品的裁切偏移，从正式线性 RGB16 TIFF 读取；亮度只在参考单张拟合一次，不对每张图另行拉伸或锐化。

输出包含单据、三张独立裁片、`ridge-comparison.png` 和 `comparison.json`。清单记录参考、入选与采用的帧、ROI、蒙版来源和显示变换。默认不保留大 TIFF；要做像素级复验可加 `--keep-intermediates`。项目代码不附带拍摄者的私有照片。

已有三份正式成品和对应的 `pipeline-report.json` 时，用 `render-only --help` 查看重做裁片的参数，无需反复解码原片。本机可单独验证一份真实单据和基准 TIFF：

```bash
python3 tests/WindowFlowTests.py ./build/NebulensWindowTests \
  --example "/path/to/example.nebprint" "/path/to/separated.tiff"
```

这条验收在隔离设置和临时输出目录里重新打开原生窗口、检查对照入口、执行正式导出，并比较完整 RGB16 像素；不会写入示例单据指定的输出目录。
