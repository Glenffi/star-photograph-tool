# StarProcessor UI 工作流

本文记录桌面工作台的信息架构、状态规则和视觉检查方法，供后续功能沿用。

## 设计目标

- 首屏按拍摄任务选择处理场景；进入后仍是服务于反复导入、检查、处理和导出的三栏工作台，不做营销页。
- 工作台采用带少量青绿色倾向的深色中性表面，蓝色用于素材选择，琥珀色用于参考帧；照片画布进一步压暗，避免界面干扰影像判断。
- 同一时刻只有一个明确主操作。素材不足时引导导入，素材就绪后突出“开始处理”。
- 只展示已实现能力；常用算法的关键取舍随当前选择紧凑呈现，完整细节保留在 tooltip 和文档中。
- 所有流程反馈来自真实程序状态，不使用可点击但没有导航能力的步骤按钮。

## 信息架构

### 场景入口

首次打开应用先选择拍摄场景。工具栏的“场景”按钮可以随时返回；已有素材不会因为返回入口而丢失。切换到另一场景时会应用与任务匹配的参数基线，并使旧处理结果失效。

| 场景 | 素材门槛 | 实际流程 |
|---|---:|---|
| 单张 RAW 精修 | 1 张 | AHD 解码 → 多尺度降噪/去雾/拉伸/缩星 → 导出，不执行对齐和堆栈 |
| 银河星景堆栈 | 2 张以上 | 质量评估 → 星点对齐 → 堆栈 → 自动优化 |
| 深空天体堆栈 | 2 张 Light + 三类校准帧 | Bayer 校准 → AHD → 质量评估 → 星点对齐 → 稳健堆栈 |
| 天地分离合成 | 固定机位 2 张以上 | 地平线蒙版 → 天空对齐堆栈 + 地景原位合成 → 边界融合 |
| 星空延时序列降噪 | 3 张以上 | RAW 预解码 → 邻帧星点对齐 → 动态保护时域降噪 → 防闪烁 → 批量输出 |

### 顶部命令

- 左侧显示产品名、当前场景和可用素材数。
- 中部提供添加照片、导入文件夹和清空项目。
- 右侧提供导出、开始处理、设置和关于。
- “开始处理”使用青绿色主强调；参考帧使用琥珀色；选中素材使用蓝色。

### 流程状态

步骤条随场景变化。堆栈场景显示素材、对齐、堆栈、结果；单张场景显示素材、调整、预览、导出；天地场景显示素材、蒙版、双路堆栈、结果；延时场景显示素材、预分析、逐帧降噪、输出序列。导入数量、worker 的 `stageMessage`、成功、取消和失败事件共同驱动状态；流程标签不可点击。

### 三栏工作台

- 素材栏：缩略图、基础 EXIF、排除状态和参考帧。首张素材在导入后自动打开。
- 预览区：适应、100%、缩放、图像信息和处理结果比较。
- 参数栏：常规任务按堆栈、调整、输出三个阶段分组；延时场景只显示滑动窗口、时域强度、动态内容保护、固定地景和输出参数。

### BCF 改机色彩还原

- “BCF 改机色彩还原”位于“调整”页，默认关闭，明确与普通相机的常规白平衡区分。
- 开启后在降噪、去雾和拉伸之前自动采样近中性天空，修正改机带来的全局 RGB 通道响应偏差；处理进度会显示实际 RGB 增益。
- 天地分离任务只从天空蒙版内取样，但增益应用于完整线性 RGB，避免地景与天空在边界处产生不同白平衡。
- 黎明、极光、强气辉或用户希望保留环境色时不应启用；当前没有手动灰点吸管。

### 延时序列交互

- 输入按文件名排序，每张 RAW 对应一张保持原文件名信息的 TIFF/PNG 输出，不生成视频。
- 3 帧窗口速度更快，5 帧窗口随机噪声抑制更明显；序列首尾自动使用能取得的相邻帧。
- “动态内容保护”默认 75。提高后，云层、草木、车辆灯光等与当前帧不同的局部区域会减少邻帧混合；静止区域仍使用完整时域降噪。该判断共用一张亮度引导图，不会造成 RGB 通道错位。
- “固定地景保持原位”开启时，天空按星点运动对齐，地景在原坐标做时域统计，最后沿自动地平线融合。
- 跨帧亮度与色偏平滑自动运行，没有额外开关。它只校正 5 帧邻域中的孤立跳变，并限制单次调整幅度，连续变亮或变暗的真实时间趋势会保留。
- 处理完成后中央预览显示序列中间帧的前后对比，状态栏显示本次输出文件夹；因为结果已经批量写出，工具栏不再重复开放单图导出。

### 深空校准交互

- 左侧素材栏只管理 Light；Dark、Flat、Bias 在参数栏“校准帧”分组分别导入，避免不同用途素材混入参考帧和质量评分。
- 每类至少 3 张才开放“开始处理”，界面建议 10–20 张；导入按钮只使用图标，数量和用途由相邻标签与 tooltip 表达。
- 三组路径只在当前会话保留，不写入预设或 `QSettings`，避免移动硬盘或拍摄目录变化后静默引用旧文件。
- 流程条显示校准、对齐、堆栈、结果；生成 Master Bias/Dark/Flat 时停留在校准阶段，实际开始星点对齐后再前进。

## 堆栈算法选择

参数栏会随当前算法显示一段简短说明，并且只在 Kappa-Sigma 模式启用 κ 控件。

| 算法 | 主要特点 | 建议场景 |
|---|---|---|
| Median | 对飞机轨迹、热像素等异常值稳健，但信噪比利用率低于平均值 | 5 帧及以下，或素材质量差异较大 |
| Mean | 信噪比与细节利用率最高，但异常轨迹和坏点容易残留 | 素材干净、曝光一致的序列 |
| Kappa-Sigma | 迭代剔除超出 κ 阈值的像素，稳健性与细节较均衡 | 6–15 帧的一般银河和深空序列 |
| Winsorized | 限制极端值后求均值，长序列中兼顾异常值抑制与信噪比 | 15 帧以上的长序列 |

## 处理前后比较

`ProcessingWorker` 在裁切共同有效区域后、执行降噪/优化/地景细节/缩星前，生成最长边 2400 px 的 8-bit 预览。处理前和处理后共享固定的完整 16-bit 显示范围及 Arcsinh 映射，避免两侧各自自动拉伸掩盖真实亮度和对比度变化。GUI 只保存这张有界预览和最终 16-bit 结果，因此不会引入第二份完整 RGB16 内存峰值。

比较模式包括：

- 处理前：完成堆栈、光度匹配和裁切后的基础结果。
- 处理后：完成当前全部收尾算法后的结果。
- 分屏：左侧处理前，右侧处理后，中线固定在 50%。

用户从结果切回单张 RAW 后，预览区显示“查看结果”，无需重新处理即可返回最近结果。

## 离屏视觉检查

应用支持开发用的 `--screenshot=<path>` 参数。macOS 无需屏幕录制权限即可生成稳定截图：

```bash
QT_QPA_PLATFORM=offscreen \
  ./build-release/StarProcessor.app/Contents/MacOS/StarProcessor \
  --screenshot=/tmp/starprocessor.png \
  /path/to/first.ARW /path/to/second.ARW
```

启动参数中的 RAW 文件会直接导入，便于检查空状态、单帧状态和长列表状态。正式视觉验收至少覆盖 1400x900、最小可用窗口、横拍、竖拍、8 张以上素材及处理结果分屏。
