# StarProcessor UI 工作流

本文记录桌面工作台的信息架构、状态规则和视觉检查方法，供后续功能沿用。

## 设计目标

- 首屏按拍摄任务选择处理场景；进入后仍是服务于反复导入、检查、处理和导出的三栏工作台，不做营销页。
- 工作台采用深色中性暗房表面，薄荷绿用于主操作和选中状态，暖金用于参考帧；照片画布进一步压暗，避免界面色彩干扰影像判断。
- 同一时刻只有一个明确主操作。素材不足时引导导入，素材就绪后突出“开始处理”。
- 只展示已实现能力；常用算法的关键取舍随当前选择紧凑呈现，完整细节保留在 tooltip 和文档中。
- 所有流程反馈来自真实程序状态，不使用可点击但没有导航能力的步骤按钮。

## 信息架构

### 场景入口

首次打开应用先选择拍摄场景。工具栏的“场景”按钮可以随时返回；已有素材不会因为返回入口而丢失。切换到另一场景时会应用与任务匹配的参数基线，并使旧处理结果失效。

| 场景 | 素材门槛 | 实际流程 |
|---|---:|---|
| 单张 RAW 精修 | 1 张 | AHD 解码 → 多尺度降噪/去雾/拉伸 → 基础调色/锐化/去紫边/缩星 → 导出，不执行对齐和堆栈 |
| 银河星景堆栈 | 2 张以上 | 质量评估 → 星点对齐 → 堆栈 → 自动优化 |
| 深空天体堆栈 | 2 张 Light + 完整校准来源 | Dark/Flat/Bias 或 Dark Flat 在 Bayer 域校准 → AHD → 质量评估 → 星点对齐 → 稳健堆栈 |
| 天地分离合成 | 固定机位 2 张以上 | 地平线蒙版 → 逐帧天空有效区变换 → 天空对齐堆栈 + 地景原位合成 → 边界融合 |
| 星轨合成 | 固定机位 3 张以上 | 帧间光度匹配 → 原坐标 Lighten/Comet → 原位地景平均 → 边界融合 |
| 星空延时序列降噪 | 3 张以上 | RAW 预解码 → 邻帧星点对齐 → 动态保护时域降噪 → 防闪烁 → 批量输出 |

### 顶部命令

- 左侧显示产品名、当前场景和可用素材数。
- 中部提供添加照片、导入文件夹和清空项目。
- 右侧提供导出、开始处理、设置和关于。
- “开始处理”使用青绿色主强调；参考帧使用琥珀色；选中素材使用蓝色。

### 流程状态

步骤条随场景变化。堆栈场景显示素材、对齐、堆栈、结果；单张场景显示素材、调整、预览、导出；天地场景显示素材、蒙版、双路堆栈、结果；星轨场景显示素材、星轨累积、地景融合、结果；延时场景显示素材、预分析、逐帧降噪、输出序列。导入数量、worker 的 `stageMessage`、成功、取消和失败事件共同驱动状态；流程标签不可点击。

### 三栏工作台

- 素材栏：缩略图、基础 EXIF、排除状态和参考帧。首张素材在导入后自动打开。
- 预览区：适应、100%、缩放、图像信息和处理结果比较。
- 参数栏：常规任务按堆栈、调整、输出三个阶段分组；星轨场景只显示彗星拖尾、方向、固定地景、通用调整和输出；延时场景只显示滑动窗口、时域强度、动态内容保护、固定地景和输出参数。

### 星轨合成交互

- 输入必须是同机位、同尺寸并按时间排序的 RAW。算法保持相机坐标，不执行星点对齐；这样恒星运动会形成轨迹，而不是重新变回点状。
- “彗星拖尾”0% 使用逐像素逐通道 Lighten。1–100% 把强度映射为时间半衰期：数值越大，较早轨迹衰减越快；“反转彗星方向”只在强度大于 0 时启用。
- 帧间光度匹配默认运行，使用首帧稀疏参考样本估计共享曝光增益和 RGB 背景偏移，减少薄云或天空亮度漂移在 Lighten 中抬高整片背景。
- “保护固定地景”默认开启。程序从序列中间帧的相机预览检测地平线，失败时回退到首帧线性亮度；天空进入星轨累积，地景在原坐标使用在线均值降噪，内存不会随帧数增长。
- 星轨场景隐藏对齐、普通堆栈、κ、质量淘汰和缩星。调整彗星强度或方向需要重新累积全部帧；降噪、改机色彩、去雾和拉伸仍可使用有界快速预览。

### BCF 改机色彩还原

- “BCF 改机色彩还原”位于“调整”页，默认关闭，明确与普通相机的常规白平衡区分。
- 开启后可使用自动灰点，也可在完成一次正式处理后点击吸管，从处理前预览中选择应为中性的天空区域。十字标记表示当前灰点，换素材、参考帧或场景会自动失效。
- 校正强度为 0–100%；它对单位增益与完整灰点增益连续插值，适合在“完全中性”和“保留部分改机暖色”之间取得平衡。
- 预览点击只保存归一化画面坐标；2400 px 快速预览和完整导出都会回到各自的线性 RGB16 缓存，以同一相对邻域重新计算中值，不读取显示曲线后的 8-bit 颜色。
- 色彩还原位于降噪、去雾和拉伸之前；处理进度会显示自动/手动模式、强度和实际 RGB 增益。
- 天地分离的自动模式只从天空蒙版内取样；手动模式由用户明确指定中性区域。两种模式的增益都应用于完整线性 RGB，避免地景与天空在边界处产生不同白平衡。
- 黎明、极光、强气辉或用户希望保留环境色时，应使用手动灰点和较低强度，或保持关闭。

### ACR 风格基础调整

- “调整”页的“基础调色”按白平衡、光线、颜色和细节分组。全部参数的中性值为 0，不再增加一个重复的总开关；任一滑块离开 0 即进入快速预览。点击处理以及正常关闭窗口时都会保存当前参数，自定义预设则显式保存整组数值。
- 色温和色调范围为 `-100..100`。色温是线性 sRGB 工作空间中的相对冷暖偏移，不代表相机元数据中的绝对 Kelvin；界面因此使用“色温偏移”名称。
- 曝光范围为 `-5.0..+5.0 EV`，内部以十分之一 EV 保存，预设和不同平台间不会因浮点序列化产生漂移。对比度、高光、阴影、白色、黑色、自然饱和度和饱和度范围为 `-100..100`。
- 明暗控制先计算联动亮度曲线，再按原 RGB 比例重建颜色；白平衡、自然饱和度和饱和度造成通道越界时，程序围绕目标亮度收敛色度，不分别硬裁切 R/G/B。这样可降低强拉伸后天空渐变出现彩色断层的风险。
- 自然饱和度优先增强低饱和区域，已经鲜艳的星云和城市辉光受到更多保护；饱和度则统一改变全部颜色。两者可以叠加，但高数值仍应检查是否超出线性 sRGB 色域。
- 锐化范围为 `0..100`，默认 0。算法只处理亮度高频，设置噪声阈值并保护深阴影与亮星核心，再按目标亮度重建 RGB。单张高 ISO RAW 建议先降噪，再从 10–35 开始；锐化不会替代降噪或反卷积。
- 正式管线顺序为：改机还原 → 降噪 → 去雾 → 自动拉伸 → 基础明暗/色彩 → 地景细节 → 亮度锐化 → 星点去紫边 → 缩星。去紫边可独立启用，只修正相对星核向外突增的色度；同时启用缩星时不会重复校正。基础曝光放在自动拉伸之后，避免百分位自动归一化抵消用户调整。
- 星空延时当前逐帧走独立的时域输出管线，因此隐藏基础调色；其余单图结果场景都共用 `FinishingPipeline`，快速预览与完整导出的算法和顺序一致。

### 天地场景的背景校正

- “检测地景”先在与中央浏览预览同尺寸的图像上生成自动硬蒙版。蓝色代表天空、绿色代表地景；检测结果本身不会被当作用户编辑，正式处理仍可在 RAW 尺寸重新检测。
- 自动结果漏掉山体、建筑或树线时，“修补地景”笔刷只提供橙色地景种子，不直接涂改最终蒙版。每次松手后，后台任务在笔迹附近运行边缘引导分割，沿颜色和亮度梯度重新求出连续边界；撤销会重新计算剩余笔迹，重置则恢复最初的自动结果。
- 精修结果以有界预览分辨率保存并进入处理签名。正式堆栈前先用最近邻放大硬分类，再按用户羽化半径在缩小工作面模糊一次，避免预览和 RAW 阶段重复羽化，也避免把软边阈值化后产生新的轮廓。
- 精修蒙版绑定生成它的照片。若处理仍使用自动参考帧，该照片会固定为正式参考帧；用户改选另一张参考帧时旧精修自动清除，必须重新检测，防止把 A 帧山脊坐标套到 B 帧。
- 笔迹不要求贴着轮廓画，只需落在漏检地景内部。透明枝叶、树冠孔洞、雾中弱边缘或地景与天空颜色非常接近时，图像本身缺少可吸附梯度，仍应改用完整用户蒙版。
- 星空对齐会同时移动整张 RGB，因此程序从羽化蒙版另建一张内缩的二值天空有效区，并对每个源帧使用相同的 Affine/Homography 变换。参考有效天空中没有被源有效区覆盖的位置会在进入天空缓存前标成无效，防止移动后的树林或山体堆出第二层轮廓；软蒙版只负责最终融合。
- 开启天地分离后，自动拉伸的低频背景模型只从天空蒙版的可靠内部取样。山体、建筑和湖面不会参与天空底色估计，避免粗网格把地景轮廓误当作光污染梯度。
- 没有足够天空样本的网格由最近的有效天空模型补齐，再做中值平滑；全地景或无有效天空的异常蒙版会安全跳过背景中和，不使用地景代替天空。
- 天空色偏校正沿羽化蒙版使用平滑缓入缓出，并采用保守强度。完全地景区域保持不变，真实雾霾、城市辉光和气辉会适度保留，不把地平线强行处理成中性灰。
- RGB 背景模型先转换为共享亮度与有符号色度偏移。色度连续减去，不再让 R/G/B 分别通过 `max(0, model-target)` 的硬拐点；亮度只在高于稳健背景目标时通过宽肩部渐进校正。这样强 Arcsinh 拉伸不会把三个不同的通道阈值放大成红、绿或蓝色环带。
- 该步骤只改变低频 RGB 背景，不执行锐化或反卷积。单张 RAW 已有的失焦、空气散射、镜头像差和曝光内星迹不会由背景校正恢复。

### 延时序列交互

- 输入按文件名排序，每张 RAW 对应一张保持原文件名信息的 TIFF/PNG 输出，不生成视频。
- 预分析进度分为元数据与资源检查、RAW 解码/星点检测、邻帧对齐、蒙版与光度分析；同一源帧在多个滑动窗口中复用时，归一化成功/跳过统计只计一次。
- 邻帧对齐、窗口降噪和逐行导出都会检查取消状态。取消后已完整写出的序列帧保留，正在写入的 TIFF 会删除，尚未开始的帧不生成。
- 3 帧窗口速度更快，5 帧窗口随机噪声抑制更明显；序列首尾自动使用能取得的相邻帧。
- “动态内容保护”默认 75。提高后，云层、草木、车辆灯光等与当前帧不同的局部区域会减少邻帧混合；静止区域仍使用完整时域降噪。该判断共用一张亮度引导图，不会造成 RGB 通道错位。
- “固定地景保持原位”开启时，天空按星点运动对齐，地景在原坐标做时域统计，最后沿自动地平线融合。
- 跨帧亮度与色偏平滑自动运行，没有额外开关。它只校正 5 帧邻域中的孤立跳变，并限制单次调整幅度，连续变亮或变暗的真实时间趋势会保留。
- 处理完成后中央预览显示序列中间帧的前后对比，状态栏显示本次输出文件夹；因为结果已经批量写出，工具栏不再重复开放单图导出。

### 深空校准交互

- 左侧素材栏只管理 Light；Dark、Flat、Bias、Dark Flat 在参数栏“校准帧”分组管理，避免不同用途素材混入参考帧和质量评分。每个角色可选择至少 3 张 RAW，或一个 StarProcessor `.spmaster` 主帧，二者互斥。
- Dark 与 Flat 始终必需。由 RAW 生成 Master Flat 时，使用 Bias 或与 Flat 同曝光的 Dark Flat 校准偏移；已经校准并按 CFA phase 归一化的 Master Flat 不重复搭配 Dark Flat。外部 Master Dark 若声明已经减去 Bias，则 Light 校准还必须提供 Bias，且程序只减一次偏置。
- 每个 RAW 组至少 3 张才开放“开始处理”，界面建议 10–20 张。勾选“保存本次生成的 Master”后，只保存本次实际由 RAW 生成的角色；所有来源和最终组合均通过后，临时目录才整体重命名到输出目录的 `Masters/时间戳`，失败不会留下半套主帧。
- 数量齐备后，参数栏明确提示会在处理开始时执行自动预检。RAW 只读取头信息，`.spmaster` 只读取结构化头，一次列出角色、相机、尺寸、ISO、曝光和重复路径问题；正式加载还会校验完整像素的 SHA-256，损坏文件不会进入校准。
- Dark 必须与 Light 同相机、ISO 和曝光；Flat 必须同相机、ISO；Dark Flat 必须匹配 Flat 曝光；Bias 必须同相机、ISO，并满足本组 Light 推导出的最短曝光上限。所有 Master 还会校验有效传感器区域、Bayer 排列、饱和值和内部校准状态。
- 预检错误使用聚合对话框显示受影响数量和示例文件；仅有建议时继续处理，并在完成后以非阻塞信息框提示。命令行报告同步写入 `calibrationPreflightWarnings`。
- 校准路径只在当前会话保留，不写入预设或 `QSettings`，避免移动硬盘或拍摄目录变化后静默引用旧文件。
- 流程条显示校准、对齐、堆栈、结果；生成或加载 Master Bias/Dark/Dark Flat/Flat 时停留在校准阶段，实际开始星点对齐后再前进。

### 深空高光保护

- 自动 Arcsinh 拉伸把稳健高光点映射到约 85%，更亮的星云核心继续使用剩余输出空间，不会把所有超过白点的样本压成同一个亮度平台。
- 高饱和发射星云可能在亮度仍有余量时先让红色或蓝色通道越界。程序从 90% 输出开始使用柔性肩部，先同比例压缩 RGB 保留色相；若完全保色会造成暗色核心，则至少保留 65% 的目标亮度，再只收敛无法装入线性 sRGB 的色度。
- 最终通道上限为 99.5%，因此 TIFF 保留后续编辑余量。该步骤只处理即将越界的高光，不改变普通星云、背景和 90% 以下星点。

## 堆栈算法选择

参数栏会随当前算法显示一段简短说明，并且只在 Kappa-Sigma 模式启用 κ 控件。

| 算法 | 主要特点 | 建议场景 |
|---|---|---|
| Median | 对飞机轨迹、热像素等异常值稳健，但信噪比利用率低于平均值 | 5 帧及以下，或素材质量差异较大 |
| Mean | 信噪比与细节利用率最高，但异常轨迹和坏点容易残留 | 素材干净、曝光一致的序列 |
| Kappa-Sigma | 迭代剔除超出 κ 阈值的像素，稳健性与细节较均衡 | 6–15 帧的一般银河和深空序列 |
| Winsorized | 限制极端值后求均值，长序列中兼顾异常值抑制与信噪比 | 15 帧以上的长序列 |

## 处理前后比较

`ProcessingWorker` 在裁切共同有效区域后、执行降噪/优化/地景细节/缩星前，生成最长边 2400 px 的 8-bit 预览。处理前和处理后共享固定的完整 16-bit 显示范围及 Arcsinh 映射，避免两侧各自自动拉伸掩盖真实亮度和对比度变化。GUI 只保存这张有界预览和最终 16-bit 结果，因此不会引入第二份完整 RGB16 内存峰值。

比较模式包括：

- 处理前：完成堆栈、光度匹配和裁切后的基础结果。
- 处理后：完成当前全部收尾算法后的结果。
- 分屏：左侧显示完整处理前图片，右侧显示完整处理后图片。适应视图按半个画布分别计算共同缩放，两侧不会再被裁成半幅；100% 下可横向滚动检查同一位置。

用户从结果切回单张 RAW 后，预览区显示“查看结果”，无需重新处理即可返回最近结果。

## 参数快速预览

完成一次正式处理后，工作台会额外保留最长边 2400 px 的线性 RGB16 堆栈缓存及对应天地蒙版。调整降噪、改机色彩、去雾、拉伸、基础调色、锐化、地景细节、去紫边或缩星参数时，应用等待 400 ms 后在后台只重跑收尾算法；继续拖动控件会取消或丢弃过期结果。对齐、堆栈、参考帧、校准帧和天地合成参数改变时不会使用该缓存。

手动再次导出完整结果由独立后台任务完成，不在 GUI 线程执行 PNG 压缩或 TIFF 写盘。导出期间锁定素材与参数编辑，并提供取消按钮；完成后继续保留内存中的正式结果供预览和再次导出。

快速结果在预览底栏持续显示“快速预览”和实际尺寸，切换 RAW 后仍可通过“查看结果”返回。快速预览只用于判断参数方向，不开放导出；用户必须点击“开始处理”生成完整分辨率结果。处理前、处理后和分屏继续使用同一显示范围，避免自动曝光掩盖参数差异。

刷新快速预览时会保留处理前/后/分屏模式、适应或手动缩放以及滚动位置。缩星对暗弱小星的改变在整图适应状态下可能小于一个显示像素，因此开启缩星后状态栏会报告实际处理星数，并提示在 100% 下复核；滑块刷新不会再把 100% 视图重置回适应窗口。

## 离屏视觉检查

应用支持开发用的 `--screenshot=<path>` 参数。macOS 无需屏幕录制权限即可生成稳定截图：

```bash
QT_QPA_PLATFORM=offscreen \
  ./build-release/StarProcessor.app/Contents/MacOS/StarProcessor \
  --screenshot=/tmp/starprocessor.png \
  /path/to/first.ARW /path/to/second.ARW
```

启动参数中的 RAW 文件会直接导入，便于检查空状态、单帧状态和长列表状态。正式视觉验收至少覆盖 1400x900、最小可用窗口、横拍、竖拍、8 张以上素材及处理结果分屏。
